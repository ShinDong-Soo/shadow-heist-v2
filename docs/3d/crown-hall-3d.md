# 3D 왕관실과 왕관 상호작용

이 문서는 Babylon.js Phase 05에서 제작한 **왕관실(Crown Hall)** 을 초보 개발자도 이해할 수 있도록 설명한다.

이번 단계의 목표는 화려한 경보 연출이 아니라, 경비의 순찰과 손전등을 읽고 엄폐물을 이용해 왕관까지 가는 작은 잠입 퍼즐을 만드는 것이다.

## 실행 방법

```powershell
npm run dev
```

브라우저에서 `http://localhost:5173/3d.html`을 연다.

| 입력 | 기능 |
|---|---|
| `WASD` | 플레이어 이동 |
| `E` | 조건을 만족했을 때 왕관 훔치기 |
| `F1` | 경비 경로·시야·왕관 범위 디버그 표시 전환 |
| `F2` | 성능·상태 패널 표시 전환 |
| `F4` | 개발용 왕관 상호작용 위치로 이동 |
| `F5` | 개발용 기둥 LOS 차단 장면으로 이동 |

`F4`와 `F5`는 `debug` 설정이 켜진 개발 버전에서만 쓰는 검증 기능이다.

## 공간 디자인

왕관실은 약 12m × 14m 크기이며 남쪽의 단일 출입구로 들어간다.

```text
북쪽 벽과 장식 패널

        [왕관 전시대]

왼쪽 안전 경로          오른쪽 빠른 경로
기둥 → 기둥 → 조각상    높은 전시물 1개

        관찰 구역
        단일 출입구
        플레이어 시작
```

- 왼쪽은 시야를 여러 번 끊을 수 있지만 이동 거리가 길다.
- 오른쪽은 왕관까지 빠르지만 열린 공간이 길다.
- 왕관 주변에는 엄폐물을 두지 않아 마지막 접근이 위험하다.
- 남쪽 벽은 카메라 방향에 있으므로 낮게 만들어 플레이어를 가리지 않게 했다.
- 문틀과 보안 게이트 레일은 Phase 06의 봉쇄 기능이 연결될 자리다.

## 엄폐물과 LOS

기둥, 조각상, 높은 전시물에는 다음 두 성질이 있다.

```text
blocksMovement = true
blocksVision = true
```

따라서 플레이어와 경비원이 통과할 수 없고, 경비의 LOS Ray도 차단한다.

유리 케이스는 다음처럼 설정했다.

```text
blocksMovement = true
blocksVision = false
```

유리를 통과할 수는 없지만 유리 뒤에 숨어 경비 시야를 피할 수도 없다. 이동 충돌과 시야 차단을 서로 다른 값으로 관리하는 이유다.

## 경비원과 손전등

경비 한 명이 왕관실 외곽과 입구 방향을 포함한 9개 지점을 순환한다.

- 플레이어가 들어왔을 때 경비는 북쪽에서 순찰을 시작한다.
- 명확한 순환 경로를 사용하므로 다음 움직임을 관찰하고 예측할 수 있다.
- 손전등과 실제 시야 방향은 Phase 04와 같은 방향 값을 사용한다.
- 왼쪽 엄폐 경로도 경비가 바깥쪽에서 확인하기 때문에 영구 안전지대가 아니다.

## 왕관 전시대

전시 구조는 역할별로 분리했다.

```text
CrownDisplay
├─ 받침대
├─ 유리 케이스
├─ 금색 프레임
└─ 목표 Spotlight

Crown
├─ 왕관 Mesh
├─ 상호작용 판정
├─ AVAILABLE / STOLEN 상태
└─ onStolen 이벤트
```

왕관은 금색 재질과 뾰족한 실루엣을 사용하고, 환경 조명보다 따뜻한 Spotlight로 강조한다. Spotlight가 영향을 주는 Mesh를 왕관·전시대·바닥으로 제한해 웹 렌더링 비용도 줄였다.

관련 코드:

- `src/3d/entities/treasure/Crown.ts`
- `src/3d/entities/treasure/CrownDisplay.ts`
- `src/3d/config/crownHallConfig.ts`

## 왕관 상호작용 조건

`E STEAL` 안내는 다음 조건을 모두 만족할 때만 나타난다.

1. 왕관에서 약 1.65m 안에 있다.
2. 유리 케이스의 정면 쪽에 서 있다.
3. 플레이어가 왕관 방향을 보고 있다.
4. 왕관 상태가 `AVAILABLE`이다.

조건을 만족하지 않으면 `E`를 눌러도 왕관이 사라지지 않는다.

## CROWN_STOLEN 이벤트

왕관은 경보나 경비 AI를 직접 실행하지 않는다.

```text
E 입력
→ Crown 상태가 STOLEN으로 변경
→ 왕관 Mesh 숨김
→ CROWN_STOLEN 이벤트 발생
→ 현재는 임시 완료 문구만 표시
```

Phase 06에서는 `GameFlowManager`가 이 이벤트 흐름을 관리해 Spotlight, 경보등, 보안 게이트, BGM과 경비 상태를 바꾼다. 자세한 내용은 [3D 왕관 강탈 시퀀스](crown-steal-sequence-3d.md)에 기록했다.

## 디버그와 실제 검증 결과

로컬 인앱 브라우저에서 다음을 확인했다.

- 시작 위치에서 `E`: `TOO_FAR`, 왕관이 `AVAILABLE`로 유지됨
- `F4` 위치: `INTERACT READY`, 상호작용 안내 활성화
- `F4` 후 `E`: 상태 `STOLEN`, 이벤트 `CROWN_STOLEN`
- `F5` 엄폐 장면: 거리 2.9m, 각도 0도에서도 중간 기둥 때문에 `BLOCKED`
- `F5` 엄폐 장면: 탐지 게이지 `CLEAR 0%` 유지
- 브라우저 콘솔 경고·오류 없음
- TypeScript 검사와 배포 빌드 통과

## 성능 최적화 기록

### 1단계: 디버그 UI 블러 제거

변경 전 디버그 패널은 움직이는 WebGL 화면을 매 프레임 흐리게 만드는 `backdrop-filter: blur(8px)`를 사용했다. Chrome Performance에서 Painting 비용이 크게 나타났기 때문에 블러를 제거하고, 글자가 잘 보이도록 배경 투명도만 높였다.

```text
변경 전: 반투명 배경 + 실시간 배경 블러
변경 후: 불투명도 94%의 단순 배경
```

조명, 그림자, Mesh와 렌더링 해상도는 변경하지 않았다. 따라서 다음 FPS 측정값은 UI 블러 제거 효과만 비교하는 기준이 된다.

### 2단계: 숨겨진 디버그와 반복 UI 갱신 중단

- 경비 시야 원뿔과 Ray를 기본 OFF로 변경했다.
- F1로 디버그를 숨기면 Ray의 선 Mesh도 더 이상 초당 20번 갱신하지 않는다.
- 성능 패널은 F2로 따로 숨길 수 있게 분리했다.
- 목표 문구와 `E STEAL` 안내는 상태가 실제로 바뀔 때만 HTML을 수정한다.

게임 규칙인 20Hz LOS 판정은 유지되므로 디버그를 꺼도 경비 탐지는 동일하게 동작한다.

### 3단계: 그림자와 조명

- 방향광 Shadow Map을 1024px에서 512px로 낮췄다.
- 방향광 필터를 Medium에서 Low로 바꿨다.
- 고정된 외곽 벽과 문틀은 방향광 그림자 생성 대상에서 제외했다.
- 경비 손전등은 벽·엄폐물·플레이어·경비만 그림자 대상으로 유지했다.
- 손전등 Bias와 Normal Bias를 줄여 두꺼운 기둥 가장자리의 빛 누출을 완화했다.
- 왕관 Spotlight는 왕관·전시대·바닥에만 영향을 준다.

### 4단계: Mesh와 Draw Call

- 여러 금색 테두리를 하나의 정적 Mesh로 병합했다.
- 북쪽 벽 패널을 하나의 정적 Mesh로 병합했다.
- 왕관 가시 6개는 같은 원본을 공유하는 Instance로 변경했다.
- 로컬 장면 Mesh 수가 69개에서 56개로 감소했다.

### 5단계: CPU 계산

- 카메라, 왕관 거리 검사와 Guard LOS가 매 프레임 만들던 임시 Vector를 재사용한다.
- 움직이지 않는 바닥·벽·전시대의 World Matrix를 고정했다.
- 플레이어, 경비, 디버그와 향후 애니메이션 대상인 왕관은 고정 대상에서 제외했다.

### 6단계: 1080p 내부 렌더링 스케일

화면의 CSS 크기는 1920×1080으로 유지하고 Babylon 내부 렌더링은 약 87% 크기로 처리한다.

```text
Hardware Scaling Level: 1.15
화면 표시 크기: 1920 × 1080
내부 렌더 비율: 약 87%
```

성능 패널에는 현재 FPS 외에 2초 구간의 `AVG`, `LOW`, `RENDER`가 표시된다. 로컬 자동 브라우저의 안정 구간에서는 다음 값을 확인했다.

```text
FPS 165 · AVG 165 · LOW 83 이상 · RENDER 87%
MESHES 56
```

이 수치는 개발 환경 결과다. 최종 합격은 사용자 PC의 배포 빌드에서 `AVG 60 이상`, 장시간 `LOW 45 미만 없음`을 확인해 결정한다.

## Phase 06으로 이동한 기능

- 왕관 집기 연출, 경보와 붉은 비상 조명, BGM 전환, 보안 게이트 폐쇄는 Phase 06에서 구현했다.
- 경비 추격·수색과 체포는 Phase 07 범위다.
- 완성형 Blender 박물관 에셋
