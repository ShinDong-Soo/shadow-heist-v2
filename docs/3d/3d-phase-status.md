# Babylon.js 3D 1·2단계 완료 현황

이 문서는 두 기획안의 완료 조건을 실제 코드와 테스트 결과에 맞춰 정리한다. 초보 개발자가 **구현 완료**와 **아직 확인하지 못함**을 혼동하지 않도록 상태를 세 가지로 나눈다.

- `완료`: 코드가 있고 로컬에서 직접 확인했다.
- `범위 밖`: 기획안에서 이번 단계에 넣지 않기로 한 기능이다.
- `남음`: 공개 배포나 다른 브라우저처럼 현재 환경만으로 완료할 수 없는 작업이다.

## 1단계: Babylon.js 3D 기반

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| Babylon.js·TypeScript·Vite | 완료 | 개발 서버와 배포 빌드 모두 실행 |
| 3D 장면·바닥·카메라 | 완료 | `/3d.html`에서 정상 표시 |
| 환경광·방향광·그림자 | 완료 | 바닥과 오브젝트에서 확인 |
| 창 크기 대응 | 완료 | 1366×768, 1600×900, 1920×1080에서 캔버스 크기 일치 |
| FPS 표시 | 완료 | 로컬 테스트에서 약 165 FPS |
| GLB 로딩 | 완료 | `test-cube.glb` 표시, 그림자와 충돌 영역 연결 |
| Blender→GLB→Babylon 파이프라인 | 완료 | 재생성 스크립트와 로더 구성 |
| 배포용 빌드 | 완료 | `npm run build` 성공, 로컬 Preview에서 콘솔 경고·오류 없음 |
| 공개 웹 주소 배포 | 완료 | GitHub Pages (`Deploy GitHub Pages` 워크플로, `main` 푸시 시 자동) |
| Edge·시크릿 모드·로그인 없는 공개 접근 | 완료 | 로그인 없이 `https://ShinDong-Soo.github.io/shadow-heist-v2/3d.html` 접속 |

현재 배포 파일은 총 약 6.98MB이고, 3D 장면 JavaScript 파일은 약 1.58MB다. 이 수치는 앞으로 모델과 애니메이션을 추가할 때 비교 기준으로 사용한다.

## 이번 수정에서 해결한 충돌 오류

이전 방식은 캐릭터가 벽과 겹치면 이동 방향의 부호만 보고 벽의 앞면이나 뒷면으로 위치를 옮겼다. 내부 모서리에서는 잘못된 면이 선택되어 캐릭터가 멀리 튕길 수 있었다.

현재 방식은 다음 순서로 동작한다.

```text
이번 프레임의 이동 거리를 작은 구간으로 나눔
→ 각 구간의 도착 위치가 안전한지 확인
→ 충돌하면 출발점과 도착점 사이를 반복해서 좁힘
→ 충돌 직전의 마지막 안전 위치에서 정지
→ 막히지 않은 다른 축은 계속 움직여 벽면을 따라 이동
```

이 방식에서는 충돌 결과가 플레이어가 요청한 이동 거리보다 커질 수 없다. 따라서 장애물 반대편으로 순간 이동하는 튕김이 구조적으로 발생하지 않는다.

## 다음에 실제로 남은 일

공개 배포와 로그인 없는 직접 접근은 GitHub Pages로 연결했다. 이후에는 저사양 PC FPS와 브라우저별 플레이 확인만 유지하면 된다.

경비원, 손전등, 실제 캐릭터 모델과 걷기 애니메이션은 1·2단계의 미완료가 아니라 다음 기획 단계의 작업이다.
