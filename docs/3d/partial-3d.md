# 부분 3D 전환

이 문서는 탑다운 잠입 화면에서 보물 앞 1인칭 장면으로 전환되는 기능을 설명한다.

## 왜 게임 전체를 바로 3D로 바꾸지 않았나

게임 전체를 3D 엔진으로 다시 만들면 이동, 충돌, 경비 AI, 시야, 문과 UI를 모두 다시 작성해야 한다. 먼저 가장 중요한 질문인 **“직접 보물을 꺼내는 장면이 기존 방식보다 재미있는가?”**를 작은 기능으로 확인한다.

이 방식을 `Vertical Slice`라고 부른다. 완성 게임 전체가 아니라 대표 장면 하나를 실제 품질에 가깝게 만들어 방향이 맞는지 시험하는 방법이다.

## 현재 플레이 흐름

```text
탑다운 화면에서 보물에 접근
→ E 입력
→ 전시대 앞 1인칭 3D 장면으로 전환
→ E를 계속 눌러 손을 뻗음
→ 진행도가 가득 차면 보물 확보
→ 기존 탑다운 화면으로 복귀
→ 보물 경보, 경계 상승, 조사 또는 추격 시작
```

`E`를 놓으면 진행도가 천천히 줄어든다. `ESC`를 누르면 보물을 훔치지 않고 원래 화면으로 돌아간다.

개발 중 장면만 바로 확인하려면 게임을 시작한 뒤 `F3`을 누른다. 이 미리보기에서 완료해도 실제 보물을 획득하거나 경보가 발생하지 않는다. 실제 게임 흐름은 보물 앞에 표시되는 `E  3D VIEW` 안내를 통해 진입한다.

## 보물별 표현

- 청동 유물: 녹청색 조각 실루엣
- 밤의 보석: 푸른 보석 실루엣
- 황금 왕관: 금색 왕관과 보석 장식

왕관은 다른 보물보다 확보 시간이 길다. 확보가 끝나면 `SECURITY BREACH`가 표시되고 기존 왕관 경보와 비상구 추격 흐름이 시작된다.

## 3D처럼 보이는 원리

현재 단계에서는 별도의 대형 3D 엔진이나 모델 파일을 내려받지 않는다. HTML 요소에 CSS의 다음 기능을 사용한다.

- `perspective`: 가까운 물체는 크게, 먼 물체는 작게 보이게 한다.
- `rotateX`, `rotateY`, `translateZ`: 벽, 바닥과 전시대가 서로 다른 깊이에 있는 것처럼 배치한다.
- 그라데이션과 그림자: 박물관의 어두운 면과 스포트라이트를 표현한다.
- 전환 애니메이션: 손, 유리 케이스와 보물이 앞뒤로 움직이게 한다.

이 방식은 실제 3D 모델보다 표현 범위는 작지만 초기 다운로드가 거의 늘지 않고 기존 Canvas 게임과 충돌할 가능성이 낮다.

## 성능과 접근성

- 외부 3D 라이브러리와 GLB 파일을 추가하지 않아 초기 로딩 부담을 최소화했다.
- 3D 장면이 열리면 기존 HUD를 숨겨 보물과 조작 안내에 집중하게 한다.
- `prefers-reduced-motion` 환경에서는 반복 움직임과 강한 전환을 정지한다.
- 장면에는 `aria-label`과 `aria-hidden` 상태를 적용해 화면 읽기 프로그램이 현재 모드를 구분할 수 있게 했다.

## 다음 판단 기준

플레이테스트에서는 다음을 확인한다.

1. 보물을 단순히 사라지게 할 때보다 직접 훔치는 느낌이 강한가?
2. 약 1초 동안 `E`를 유지하는 행동이 긴장감을 만드는가, 불편하기만 한가?
3. 왕관 확보 직후 경보와 추격으로 넘어가는 변화가 인상적인가?
4. 저사양 PC의 Chrome과 Edge에서도 전환이 부드러운가?

반응이 좋으면 다음 단계에서 왕관실 한 공간만 Babylon.js 또는 WebGL 기반 실제 3D로 제작한다. 반응이 약하면 전체 3D 전환에 비용을 쓰지 않고 현재 Fake 2.5D와 조명 연출을 강화한다.
