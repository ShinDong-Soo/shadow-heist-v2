# 3D Guard AI FSM 이식 — Phase 10

이 문서는 2D 프로토타입에서 사용하던 경비원 판단 흐름을 Babylon.js 3D 장면에 옮긴 내용을 초보 개발자도 따라갈 수 있도록 정리한다.

## 한눈에 보는 결과

경비원은 이제 단순히 정해진 길만 걷지 않는다. 플레이어를 잠깐 보거나, 발소리를 듣거나, 왕관 경보를 받으면 원인을 확인하러 간다. 플레이어를 놓친 뒤에도 현재 위치를 몰래 추적하지 않고 마지막으로 확인한 정보만 이용해 제한적으로 수색한다.

```text
PATROL
  ├─ 희미하게 봄 → SUSPICIOUS → INVESTIGATE
  ├─ 소리를 들음 ─────────────→ INVESTIGATE
  └─ 확실히 봄 ───────────────→ CHASE

INVESTIGATE → SEARCH → RETURN → PATROL
       ↑          │
       └─ 재발견 ─┴────────────→ CHASE

CHASE → 시야 상실 0.75초 → INVESTIGATE → SEARCH
CHASE → 가까이 붙음 → CAPTURE
```

## AI 상태

### PATROL — 순찰

- 지정된 웨이포인트 사이를 이동한다.
- 지점에 도착하면 잠깐 멈추고 주변을 확인한다.
- 경보 중에는 더 빠르게 움직이고 손전등을 더 적극적으로 훑는다.

### SUSPICIOUS — 의심

- 플레이어를 확실히 보지는 못했지만 수상한 모습을 발견한 상태다.
- 즉시 달려들지 않고 짧은 반응 시간을 둔다.
- 계속 보이면 `CHASE`, 놓치면 마지막으로 본 곳을 `INVESTIGATE`한다.

### INVESTIGATE — 조사 이동

- 마지막 목격 지점, 발소리 위치, 경보 위치 또는 목격한 Locker로 이동한다.
- 추격보다 느린 속도를 사용해 조사와 추격이 움직임만으로 구분된다.
- 목표 지점에 도착하면 `SEARCH`로 전환한다.

### CHASE — 추격

- LOS로 확인한 플레이어 위치만 갱신한다.
- 시야가 끊기면 0.75초 동안 마지막 이동 방향을 아주 짧게 예측한다.
- 그 뒤에는 플레이어의 현재 위치를 더 이상 읽지 않고 마지막 예상 위치를 조사한다.
- 충분히 가까워지면 `CAPTURE`로 전환해 실패 처리를 실행한다.

### SEARCH — 주변 수색

- 마지막으로 알고 있는 위치 주변에 3개의 수색 지점을 만든다.
- 경보 중에는 수색 지점이 4개, 수색 시간이 30% 늘어난다.
- 벽이나 전시대 안에 들어가는 지점은 충돌 검사로 제외한다.
- 완전 무작위 대신 생성할 때마다 좌우 패턴만 바뀌어 억울한 결과를 줄였다.
- 수색 도중 새 발소리를 들으면 그 위치를 다시 조사하고, 플레이어를 보면 추격한다.

### RETURN — 순찰 복귀

- 수색이 끝난 자리에서 순간이동하지 않는다.
- 현재 위치와 가장 가까운 순찰 지점까지 직접 이동한 뒤 `PATROL`로 돌아간다.

### CAPTURE — 체포

- 이동을 멈추고 게임 실패 흐름을 호출한다.

## 기억 시스템

`GuardMemory`는 경비원이 알고 있는 정보와 모르는 정보를 분리한다.

- `lastSeenPosition`: 마지막으로 실제 확인한 플레이어 위치
- `lastSeenTime`: 마지막 목격 시각
- `lastHeardPosition`: 마지막으로 들은 소리의 위치
- `lastHeardTime`: 마지막 청취 시각
- `lastKnownPlayerDirection`: LOS가 끊기기 직전의 제한적인 이동 방향
- `lastKnownHideSpot`: 경비원이 플레이어 진입을 직접 본 은신처

핵심 규칙은 LOS가 끊긴 뒤 `player.position`을 계속 읽지 않는 것이다. 이 규칙 덕분에 플레이어가 모퉁이를 돌아 도망치거나 경비원이 보지 못한 Locker에 숨는 선택이 의미를 가진다.

## 소리와 자극 우선순위

`NoiseSystem`이 걷기, 달리기, Locker 문, 왕관 등에서 소리 이벤트를 만들고 `GuardHearing`이 실제 청취 범위 안의 새 이벤트만 전달한다.

우선순위는 다음과 같다.

1. 플레이어 직접 발견
2. 목격한 은신처
3. Lockdown 수색 명령
4. 왕관 경보
5. 무전 보고
6. 큰 소음
7. 일반 소음

따라서 추격 중 발소리가 들렸다고 갑자기 조사를 시작하지 않으며, 왕관 경보를 조사하던 경비원이 더 약한 일반 발소리에 계속 끌려 다니지 않는다.

## 경보와 Lockdown

경보는 새로운 AI 상태가 아니라 기존 상태를 강화하는 전역 보정값이다.

- 이동 속도: 15% 증가
- 수색 시간: 30% 증가
- 수색 지점: 3개에서 4개로 증가
- 반응 시간: 10% 감소
- 시야 거리: Guard Vision의 경보 보정 적용

왕관 경보가 발생하면 플레이어가 보이지 않는 경비원은 왕관 위치를 조사한다. 이미 플레이어를 확실히 보고 있는 경비원은 경보 위치로 샛길을 타지 않고 추격을 유지한다.

## 은신처와 연결

- 경비원이 Locker 진입을 직접 봤을 때만 해당 Locker를 기억한다.
- 직접 보지 못한 Locker는 임의로 열지 않는다.
- 목격 은신 또는 Lockdown 장기 은신 조사에서는 수색 동작 뒤 Locker 발견 처리를 실행한다.

## 이동, 애니메이션, 손전등

- `GuardNavigation`이 목표점 이동과 벽 미끄러짐 충돌을 전담한다.
- 정면이 막히면 좌우 접선 이동을 비교해 단순 장애물에서 빠져나온다.
- `GuardAnimationController`가 FSM 상태와 실제 이동 여부를 받아 순찰, 조사, 수색, 추격, 복귀 동작을 구분한다.
- 손전등은 경비원의 실제 회전 방향과 FSM 집중 상태를 사용하므로 몸과 다른 곳을 비추지 않는다.

## 테스트 영상 피드백 보완

이번 보완은 `Search 정체 복구 → Search Point 개선 → 60FPS 최적화 → 상태 연출 강화 → UI 정리` 순서로 진행했다.

### Search 정체 복구

- 목표까지 남은 거리가 실제로 줄어드는지 누적해서 확인한다.
- 벽 모서리에서 좌우로 조금 흔들리기만 하는 움직임은 전진으로 인정하지 않는다.
- `SEARCH`가 약 0.72초 동안 진전하지 못하면 현재 지점을 포기하고 다음 지점으로 이동한다.
- `INVESTIGATE`와 `RETURN`에도 별도의 정체 제한 시간을 두어 AI가 영구 정지하지 않게 했다.

초보 개발자가 기억할 핵심은 **캐릭터가 움직였는가**보다 **목표에 가까워졌는가**를 검사해야 한다는 점이다. 벽에 붙어 미끄러지는 캐릭터는 화면상 움직여도 목적지에는 도착하지 못할 수 있다.

### Search Point 개선

- 마지막 목격 위치 주변을 한 개 반경으로만 찍지 않고 4개의 반경과 8개의 방향 후보에서 고른다.
- 충돌할 수 없는 위치와 서로 너무 가까운 위치는 제외한다.
- 이동 중 막힌 지점은 버리고 남은 수색 지점을 계속 사용한다.
- 스캔 중에는 고개와 손전등이 오른쪽, 왼쪽, 정면 순서로 공간을 훑는다.

### 60FPS 최적화

- 처음에는 화면을 80% 내부 해상도로 렌더링한다.
- 평균 FPS가 50 아래로 내려가면 내부 해상도를 단계적으로 낮춰 부하를 줄인다.
- 평균 FPS가 58 이상으로 안정되면 화질을 단계적으로 복원한다.
- 손전등 그림자 맵을 256px로 낮추고 매 프레임이 아니라 2프레임마다 갱신한다.
- 미션 UI의 DOM 갱신을 초당 약 20회로 제한한다.

내부 해상도 조절은 CSS 화면 크기를 바꾸는 기능이 아니다. 같은 화면 크기에서 3D 장면을 조금 작은 해상도로 그린 뒤 확대해 GPU가 처리할 픽셀 수를 줄이는 방식이다.

### 상태 연출 강화

- `SUSPICIOUS`에서는 상체가 긴장하고 고개가 짧게 주변을 확인한다.
- `SEARCH`에서는 상체와 고개, 손전등이 더 넓고 느리게 공간을 훑는다.
- `CHASE`에서는 손전등 흔들림을 키우고, 집중 조사 중에는 흔들림을 줄였다.
- 상태에 따라 손전등 움직임이 달라져 텍스트를 읽지 않아도 경비원의 의도를 짐작할 수 있다.

### UI 정리

- Debug 패널은 기본적으로 숨기고 `F2`로 열도록 변경했다.
- 화면 하단에는 이동, 달리기, 웅크리기, 상호작용, 재시작만 먼저 보인다.
- 개발용 단축키는 접을 수 있는 `TEST KEYS` 안으로 옮겼다.
- Debug 패널이 화면 높이를 넘으면 패널 안에서만 스크롤되도록 제한했다.

## 디버그 정보

개발용 Debug HUD와 장면 표시는 다음 정보를 제공한다.

- 현재 FSM 상태
- 직전 상태 전환과 이유
- 마지막 목격·청취 정보의 경과 시간
- 현재 조사/이동 목표
- 마지막 목격 위치와 청취 위치 Marker
- 생성된 Search Point
- 현재 Navigation Line

상태가 바뀔 때 브라우저 Console에도 `PATROL -> INVESTIGATE (FOOTSTEP)`과 같은 로그가 남는다.

## 코드 구성

- `GuardController.ts`: 상태를 조합하고 외부 사건을 받는 중심 관리자
- `GuardStateMachine.ts`: 상태 등록, 갱신, 전환 순서 관리
- `GuardMemory.ts`: 목격·청취·은신처 기억
- `GuardNavigation.ts`: 3D 이동과 충돌 회피
- `GuardSearch.ts`: 수색 지점 생성과 순환
- `GuardHearing.ts`: 새 소리 이벤트 청취
- `GuardRadio.ts`: 향후 경비원 여러 명을 위한 무전 이벤트 구조
- `guardAIConfig.ts`: 속도, 반응 시간, 수색 시간, 경보 보정값

## 초보 개발자를 위한 수정 위치

경비원이 너무 빠르거나 수색이 길다면 먼저 `src/3d/config/guardAIConfig.ts`만 수정한다. 상태 전환 규칙을 바꾸고 싶다면 `GuardController.ts`에서 해당 `enter...`와 `update...` 쌍을 찾는다. 이동 충돌 문제는 상태 코드가 아니라 `GuardNavigation.ts`에서 확인하는 것이 가장 빠르다.
