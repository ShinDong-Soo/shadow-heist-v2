# 3D 플레이어 이동과 탑다운 카메라

이 문서는 Babylon.js Phase 02에서 구현한 임시 플레이어, 이동, 충돌, 추적 카메라를 초보 개발자 기준으로 설명한다. 캐릭터 모델과 애니메이션은 아직 넣지 않았다.

## 실행과 조작

개발 서버를 실행하고 `http://localhost:5173/3d.html`을 연다.

| 키 | 기능 |
|---|---|
| `WASD` / 방향키 | 카메라 화면 기준 이동 |
| 마우스 오른쪽 버튼 + 좌우 드래그 | 마우스를 움직인 거리만큼 카메라 좌우 회전 |
| `1` | Near 카메라 7.6m |
| `2` | Medium 카메라 9.4m, 기본값 |
| `3` | Far 카메라 12.2m |
| `R` | 카메라 각도와 거리를 기본값으로 복원 |

휠 확대는 막아 두었다. 카메라 회전은 마우스 오른쪽 버튼을 누른 채 마우스를 좌우로 움직일 때만 작동하고, 버튼을 놓으면 마지막 각도를 유지한다. 드래그하는 거리가 길수록 더 많이 회전한다. `1·2·3`은 개발 중 화면 크기를 비교하기 위한 임시 디버그 기능이다.

## 코드 구조

```text
src/3d/
├─ systems/InputManager.ts
├─ entities/player/Player.ts
├─ entities/player/PlayerController.ts
├─ camera/GameCamera.ts
├─ config/gameConfig.ts
└─ scenes/PrototypeScene.ts
```

- `InputManager`: 현재 눌린 WASD 상태를 저장한다. 브라우저가 흐려지거나 다른 탭으로 이동하면 입력을 초기화한다.
- `Player`: `PlayerRoot`, 임시 Capsule, `CameraTarget`, `InteractionPoint`를 만든다.
- `PlayerController`: 카메라 기준 방향, 속도, 가감속, 회전, 충돌을 계산한다.
- `GameCamera`: 플레이어 추적, 부드러운 보간, Look Ahead와 거리 프리셋을 담당한다.
- `gameConfig`: 이동 속도와 카메라 수치를 한곳에서 조정한다.
- `PrototypeScene`: 이동 검증용 방, 통로, 벽과 상자를 배치한다.

## 플레이어 구조

```text
PlayerRoot
├─ Capsule Visual
├─ Facing Marker
├─ CameraTarget
└─ InteractionPoint
```

`PlayerRoot`가 실제 위치와 Y축 회전을 가진다. 청록색 캡슐은 키 1.76m를 가정한 임시 캐릭터이며, 노란 표식이 바라보는 방향을 알려준다. 충돌 반경은 0.38m다.

## 이동 계산

입력은 세계의 X/Z 방향으로 바로 바꾸지 않는다. 카메라가 바라보는 수평 방향을 `앞`, 그에 직각인 방향을 `오른쪽`으로 계산한다. 따라서 카메라 각도가 달라도 `W`는 항상 화면 위쪽, `D`는 화면 오른쪽으로 움직인다.

대각선 입력은 벡터 길이를 1로 정규화한다. 이 처리가 없으면 `W+D`가 `W`보다 약 1.41배 빨라진다. 이동 거리는 `속도 × deltaTime`으로 계산해 FPS가 달라도 같은 시간에 비슷한 거리를 이동한다.

현재 기본 걸음 속도는 3.35m/s다. 목표 속도까지 짧게 가속하고 키를 놓으면 더 빠르게 감속하므로 부드럽지만 미끄럽지 않게 구성했다. 달리기·웅크리기 속도는 설정에 준비했지만 이번 단계에서는 입력에 연결하지 않았다.

## 회전

이동 중에는 캡슐이 이동 방향을 바라본다. 180도 방향 전환도 한 프레임에 순간이동하지 않고 짧게 보간한다. 정지하면 마지막 방향을 유지한다.

## 충돌

이번 단계에서는 물리 엔진 대신 플레이어의 원형 발판과 벽의 사각 영역이 겹치는지 검사한다. X 이동과 Z 이동을 따로 해결하므로 벽을 비스듬히 밀었을 때 완전히 멈추지 않고 벽면을 따라 미끄러진다.

충돌 위치는 이동 방향만 보고 벽의 한쪽으로 강제 이동시키지 않는다. 현재 위치에서 이번 프레임에 가려는 위치 사이를 작은 구간으로 나누고, 각 구간에서 **충돌하기 직전의 마지막 안전 위치**를 찾는다. 따라서 내부 벽이나 L자 모서리에 부딪혀도 장애물 반대편으로 튕겨 나가지 않는다.

코드로 만든 벽과 주황색 상자뿐 아니라 GLB로 불러온 갈색 시험 상자에도 같은 사각 충돌 영역을 지정했다. 화면에 장애물처럼 보이는 물체를 통과하는 혼란을 막기 위한 처리다.

테스트 장면에는 다음이 포함된다.

- 바깥 경계 벽
- 시작 방
- 폭 2.4m 출입구와 좁은 통로
- 모서리 이동을 확인하는 L자 벽
- 대각선 충돌을 확인하는 1.55m 상자

점프, 계단, 중력, 벽 투명화는 이번 범위에 없다.

## 카메라

카메라는 플레이어 메시가 아니라 몸통 높이 0.92m의 `CameraTarget`을 기준으로 움직인다. 다만 플레이어 위치를 매 프레임 그대로 따라가지는 않는다. 화면 기준 좌우 1.2m, 앞뒤 0.8m의 **데드존** 안에서는 카메라를 고정하고, 플레이어가 영역 밖으로 나간 거리만 부드럽게 따라간다.

데드존은 플레이어가 조금 걷거나 벽 앞에서 방향을 바꿀 때 생기던 잦은 카메라 보정을 없앤다. 이동 방향을 더 보여주는 Look Ahead도 기존 0.72m에서 0.18m로 줄이고 별도로 천천히 보간한다. 따라서 짧은 방향 전환은 화면을 흔들지 않으면서, 오래 이동하면 앞으로 갈 공간은 계속 확보한다.

기본 카메라는 약 50도 FOV와 고정 하이앵글을 사용한다. 벽 투명화 없이도 플레이어와 주변 1~2개 공간을 함께 읽을 수 있는 거리로 9.4m를 선택했다.

왕관실에서 Escape 단계가 시작되면 카메라는 북쪽 침투 시점에서 남쪽 탈출 시점으로 부드럽게 180도 전환한다. 따라서 플레이어보다 먼저 Archive와 출구 방향을 화면에 보여준다. 이후 사용자는 마우스 오른쪽 버튼을 누른 채 마우스를 좌우로 드래그해 위험 방향을 추가로 확인할 수 있다. 방향키와 `WASD`는 카메라에 사용되지 않고 항상 플레이어 이동만 담당한다.

## 디버그 정보

오른쪽 위 패널에서 다음을 확인할 수 있다.

- FPS
- 카메라 거리와 높이
- 메시 개수
- 현재 속도와 이동 방향
- 현재 수신 중인 키 (`INPUT W`, `INPUT A+D` 등)
- 플레이어 X/Y/Z 위치

키를 눌러도 움직이지 않는다면 먼저 3D 화면을 한 번 클릭한다. 오른쪽 위가 `INPUT NONE`에서 `INPUT W`처럼 바뀌는지 확인한다. 입력은 Canvas 포커스에만 의존하지 않도록 문서의 캡처 단계에서 받고, 한글 입력 상태에서도 물리 키 위치를 나타내는 `KeyboardEvent.code`를 우선 사용한다.

초기 Phase 02에서는 첫 입력 시 `getForwardRay()`가 필요한 `Ray` 모듈을 찾지 못해 이동 루프가 중단되는 문제가 있었다. Babylon을 세부 경로로 불러올 때 필요한 부수 효과 모듈을 `PlayerController`에서 명시적으로 등록해 해결했다.

## 테스트 체크리스트

- `W`, `A`, `S`, `D`가 화면 방향과 일치하는가?
- `W+D`가 직선보다 빠르지 않은가?
- 키를 놓으면 짧게 감속한 뒤 멈추는가?
- 방향 전환이 빠르지만 한 프레임에 튀지 않는가?
- 출입구를 통과할 수 있는가?
- 벽과 상자를 통과하지 않는가?
- 모서리를 비스듬히 밀 때 벽면을 따라 이동하는가?
- 내부 벽에 여러 번 연속으로 밀어도 반대편으로 튀지 않는가?
- 코드 상자와 GLB 상자가 모두 같은 방식으로 충돌하는가?
- 이동 중 카메라가 부드럽게 따라오는가?
- 데드존 안의 짧은 이동에서 카메라가 고정되는가?
- 데드존을 벗어나면 초과한 거리만 따라오는가?
- 정지 후 카메라가 추가로 흔들리거나 밀리지 않는가?
- Escape 시작 시 카메라가 남쪽 탈출 경로를 먼저 보여주는가?
- 마우스 오른쪽 버튼을 누른 상태에서 마우스를 좌우로 드래그하면 카메라만 회전하는가?
- 우클릭 중에도 방향키와 `WASD`가 계속 플레이어를 이동시키는가?
- 마우스 오른쪽 버튼을 놓으면 `←/→`가 다시 이동 입력으로 동작하는가?
- 다른 창으로 이동했다 돌아왔을 때 계속 걷지 않는가?
- 창 크기를 변경해도 캔버스가 맞춰지는가?
