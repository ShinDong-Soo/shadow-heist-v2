# 3D 경비 순찰과 손전등

이 문서는 Babylon.js Phase 03에서 추가한 경비원 한 명의 순찰과 손전등을 설명한다. 이번 단계의 목표는 경비가 플레이어를 잡는 것이 아니라, **경비 몸이 보이기 전에 벽과 바닥에 나타나는 빛으로 접근 방향을 느끼게 하는 것**이다.

## 확인 방법

개발 서버를 실행하고 `http://localhost:5173/3d.html`을 연다.

| 입력 | 기능 |
|---|---|
| `WASD`·방향키 | 플레이어 이동 |
| `1`·`2`·`3` | 카메라 Near·Medium·Far 비교 |
| `R` | 기본 Medium 카메라로 초기화 |
| `F1` | 경비 순찰 경로와 디버그 패널 숨기기·표시하기 |

청록색 선은 경비가 걸을 길이고 흰 점은 정지할 위치다. 주황색 짧은 선은 경비가 보는 방향, 노란색 선은 손전등 방향을 나타낸다. 이 표시는 개발 확인용이며 실제 게임 화면에서는 숨긴다.

## 코드 구조

```text
src/3d/
├─ config/guardConfig.ts
├─ entities/guard/
│  ├─ Guard.ts
│  ├─ GuardController.ts
│  ├─ GuardPatrol.ts
│  ├─ GuardFlashlight.ts
│  └─ GuardDebugView.ts
└─ systems/CollisionWorld.ts
```

- `guardConfig`: 경비 크기·속도·회전·정지 시간·손전등 수치를 한곳에서 관리한다.
- `Guard`: 경비 몸체와 손전등·탐지·길찾기 기준점을 만든다.
- `GuardPatrol`: 8개 순찰 지점과 현재 목표 지점을 관리한다.
- `GuardController`: 정지·회전·이동 상태를 바꾸고 실제 위치를 계산한다.
- `GuardFlashlight`: SpotLight, 약한 흔들림과 동적 그림자를 담당한다.
- `GuardDebugView`: 순찰 경로와 방향을 개발자에게 보여준다.
- `CollisionWorld`: 플레이어와 경비가 같은 충돌 규칙을 사용하게 한다.

## 경비 구조

```text
GuardRoot
├─ 임시 Capsule 몸체
├─ 모자와 손전등 모형
├─ FlashlightPivot
│  └─ SpotLight
├─ DetectionOrigin
└─ NavigationTarget
```

경비 높이는 1.88m, 충돌 반경은 0.42m다. 플레이어보다 조금 크고 어두운 제복색을 사용해 임시 모델이어도 서로 구분된다. `DetectionOrigin`은 다음 Phase 04의 LOS 시작점이고, 이번 단계에서는 탐지 계산에 사용하지 않는다.

## 순찰 상태

경비는 세 상태만 사용한다.

```text
PATROL
목표 지점까지 1.85m/s로 이동
↓
IDLE
도착한 곳에서 0.65초 정지
↓
TURN
다음 지점을 향해 천천히 회전
↓
PATROL
```

목표 지점에 도착하자마자 순간적으로 방향을 바꾸지 않는다. 멈춘 뒤 몸과 손전등이 함께 공간을 훑고 나서 이동하기 때문에 다음 방향을 플레이어가 읽을 수 있다.

순찰 좌표는 Controller 안에 넣지 않고 `GUARD_PATROL_ROUTE` 데이터로 분리했다. 나중에 박물관 맵이 바뀌어도 이동 코드를 고치지 않고 경로만 교체할 수 있다.

## 손전등과 그림자

손전등은 Babylon.js `SpotLight`를 사용한다.

- 높이 1.38m
- 거리 9.2m
- 각도 44도
- 약간 따뜻한 색
- 경비가 걸을 때 매우 작은 좌우·상하 흔들림
- 512px 동적 그림자

SpotLight는 경비의 `FlashlightPivot` 자식이다. 따라서 경비가 회전하면 손전등과 그림자도 같은 방향으로 움직인다. 바닥뿐 아니라 벽·기둥·상자에 빛이 나타나며, 벽 뒤에서는 경비 몸보다 밝은 빛이 먼저 보일 수 있다.

화면에 큰 2D 시야 삼각형은 표시하지 않았다. 현재 빛은 위험 방향을 알려주는 시각 정보이고, 실제 탐지 범위는 다음 단계에서 LOS와 Raycast로 연결한다.

### 어두운 박물관과 손전등 순찰

2026-08-26 전역 환경광과 키 조명을 거의 끄고, 플레이어 주변만 밝히는 로컬 PointLight를 추가했다. 맵 전체가 한눈에 보이던 상태를 없애고, 경비원은 손전등 빛으로만 멀리서 읽히도록 맞췄다.

- 환경광·방향광은 `GAME_3D_CONFIG.lighting`의 낮은 값만 유지한다.
- `PlayerVisionLight`가 플레이어 주변 약 6.4m만 밝힌다. 웅크리거나 Locker에 들어가면 범위가 줄어든다.
- 경비 SpotLight는 거리 9.2m·세기 8.4로 올려 어두운 맵에서도 순찰 원뿔이 선명하다.
- 실제 탐지 거리도 손전등 도달 거리에 맞춰 9.2m로 맞췄다.
- 바닥·선반의 자체 발광(emissive)을 줄여 멀리 있는 방이 윤곽만으로 드러나지 않게 했다.
- 플레이어 로컬 조명 추가에 맞춰 동시 조명 상한을 10개로 올렸다.

### 전체 박물관에서 손전등이 사라지던 문제 수정

2026-08-26 전체 박물관에는 환경광, 왕관 조명, CCTV와 경보등이 함께 존재해 Babylon.js `StandardMaterial`의 기본 동시 조명 수 4개를 넘었다. 이때 뒤에 등록된 경비원 손전등이 재질의 활성 조명 목록에서 빠져, 경비원이 손전등을 들고 있어도 바닥과 벽이 밝아지지 않는 문제가 있었다.

- 박물관 재질의 동시 조명 수를 먼저 8개로 조정했고, 이후 플레이어 로컬 조명 추가 때 10개로 올렸다.
- 두 경비원의 SpotLight에 높은 우선순위를 부여했다.
- `west`, `east` 식별자를 조명 이름에 넣어 각 손전등과 그림자를 따로 확인할 수 있게 했다.
- 낮음 그래픽 품질에서도 벽과 바닥에 빛이 표시되는 것을 확인했다.
- 기둥과 선반에 막힌 빛이 반대편까지 통과하지 않는 것을 확인했다.

동시 조명 수는 빛을 새로 여러 개 만드는 설정이 아니다. 이미 존재하는 조명 중 한 재질이 동시에 계산할 수 있는 상한만 늘린 것이며, SpotLight 범위 밖의 오브젝트에는 적용되지 않는다.

## 충돌

경비도 플레이어와 같은 원형 충돌 계산을 사용한다. 한 프레임의 이동을 작은 구간으로 나누고 충돌 직전 위치까지만 이동하므로, 벽을 통과하거나 장애물 반대편으로 튀지 않는다.

현재 경로는 장애물과 충분히 떨어져 있지만, 이후 경로 좌표를 잘못 배치하더라도 경비가 벽을 그대로 관통하지 않게 하는 안전장치다.

## 실제 확인 결과

2026-08-25 로컬 개발 화면에서 확인했다.

- `PATROL`, `IDLE`, `TURN` 세 상태가 모두 반복됨
- 8개 웨이포인트를 순서대로 순환
- 경비 회전과 손전등 방향 일치
- 벽과 상자에 손전등 빛 표시
- 동적 경비·환경 그림자 표시
- F1을 눌렀을 때 디버그 표시가 숨겨지고 다시 나타남
- 플레이어의 기존 2.4m 출입구 통과와 충돌 정상
- 약 0.4m의 짧은 이동과 짧은 좌우 방향 전환에서는 카메라 목표가 고정됨
- 카메라는 데드존을 벗어난 뒤에만 이동하고 정지 후 추가 흔들림 없음
- 1080p에서 약 165 FPS, 메시 29개
- 브라우저 콘솔 경고·오류 0개

FPS는 컴퓨터와 브라우저 상태에 따라 달라진다.

## 이번 단계에서 넣지 않은 기능

다음은 오류나 누락이 아니라 Phase 04 이후 범위다.

- 플레이어 시야 탐지
- 의심·조사·수색
- 추격·체포
- 무전과 경보
- 실제 경비 캐릭터 모델과 걷기 애니메이션
- 전체 발소리 시스템

공개 URL 배포, Edge와 시크릿 모드 확인도 외부 배포 주소를 만든 뒤 진행한다.

## 다음 단계

Phase 04에서는 손전등 방향을 실제 위험 영역과 연결한다.

```text
거리 확인
→ 시야각 확인
→ Guard와 Player 사이 Raycast
→ 벽에 막혔는지 확인
→ 탐지 게이지 증가 또는 감소
```

그때도 손전등 모양과 실제 탐지 범위가 크게 어긋나지 않는지 가장 먼저 확인한다.
