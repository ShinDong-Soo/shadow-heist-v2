# 3D LOS와 플레이어 탐지

이 문서는 Babylon.js Phase 04에서 구현한 경비 시야와 누적 탐지를 설명한다. 목표는 단순히 가까이 있는 플레이어를 발견하는 것이 아니라, **거리·방향·벽을 모두 확인해 플레이어가 왜 들켰는지 이해할 수 있게 하는 것**이다.

## 확인 방법

개발 서버를 실행하고 `http://localhost:5173/3d.html`을 연다. 플레이어가 위쪽 순찰 구역으로 들어가 손전등 앞에 서면 탐지 게이지가 올라간다. 벽이나 큰 상자 뒤로 이동하면 게이지가 서서히 내려간다.

`F1`은 모든 경비 디버그 표시를 숨기거나 다시 표시한다.

- 파란 부채꼴 선: 최대 8m, 총 90도의 시야 범위
- 초록 Ray: 거리·각도·벽 검사를 통과해 플레이어를 보는 중
- 빨간 Ray: 벽이나 큰 오브젝트가 시야를 막음
- 회색 Ray: 거리 밖 또는 시야각 밖
- `VISION`: 현재 판정, 거리, 각도, 초당 검사 횟수
- `DETECTION`: 누적 탐지 상태와 백분율

이 콘과 Ray는 판정 확인용이다. 최종 플레이에서는 손전등과 경비 움직임만으로 위험 방향을 전달하고 디버그 그래픽은 숨긴다.

## 코드 구조

```text
src/3d/
├─ config/guardVisionConfig.ts
├─ entities/guard/GuardVision.ts
├─ systems/DetectionSystem.ts
├─ entities/guard/GuardController.ts
└─ entities/player/Player.ts
```

- `guardVisionConfig`: 거리·각도·탐지 시간·검사 주기를 관리한다.
- `GuardVision`: 거리와 각도를 확인하고 실제 3D Raycast를 실행한다.
- `DetectionSystem`: 보이는 시간에 따라 게이지와 상태를 변경한다.
- `GuardController`: 의심·발견 시 순찰을 멈추고 마지막 목격 위치를 바라본다.
- `Player`: 발이 아닌 상체를 검사하도록 `DetectionTarget`을 제공한다.

## 시야 검사 순서

```text
1. 경비 눈과 플레이어 상체의 거리 확인
↓
2. 손전등 방향과 플레이어 방향의 각도 확인
↓
3. 두 조건을 통과할 때만 Raycast
↓
4. Ray가 벽·기둥·큰 상자에 먼저 닿으면 BLOCKED
↓
5. 아무것도 막지 않으면 VISIBLE
```

거리 밖이거나 뒤쪽에 있는 플레이어에게는 Raycast를 실행하지 않는다. 검사는 0.05초마다 한 번, 약 20Hz로 동작한다. 탐지 게이지는 매 프레임의 Delta Time을 사용해 부드럽게 변한다.

## 현재 밸런스

| 설정 | 값 | 쉬운 설명 |
|---|---:|---|
| Vision Range | 8m | 이 거리보다 멀면 보지 못함 |
| Vision Angle | 90도 | 정면 좌우 45도 범위 |
| Detection Time | 1.2초 | 계속 보았을 때 100%가 되는 시간 |
| Decay Time | 1.8초 | 완전히 놓쳤을 때 0%가 되는 시간 |
| Suspicious | 35% | 경비가 순찰을 멈추는 기준 |
| Vision Check | 20Hz | 초당 약 20번 시야 검사 |

이 수치는 정답이 아니라 이후 플레이테스트에서 조정할 시작값이다.

## 탐지 상태

```text
CLEAR
0~34%, 기존 순찰 유지
↓
SUSPICIOUS
35~99%, 순찰을 멈추고 마지막 목격 위치를 천천히 확인
↓
DETECTED
100%, 정지한 채 마지막 목격 위치를 더 빠르게 바라봄
```

플레이어가 시야에서 사라지면 값이 즉시 0이 되지 않고 1.8초 동안 감소한다. `DETECTED`에서 값이 내려가면 `SUSPICIOUS`, 이후 `CLEAR`로 돌아가 순찰을 재개한다.

경비는 벽 너머의 현재 플레이어 좌표를 알지 못한다. 마지막으로 실제 Raycast가 통했던 위치만 기억한다. 따라서 플레이어가 엄폐 뒤에서 움직여도 경비가 벽을 통해 정확히 따라보지 않는다.

## 이동 차단과 시야 차단

이동 충돌과 LOS는 별개로 관리한다.

```text
blocksMovement
플레이어나 경비가 통과할 수 있는가?

blocksVision
Guard Ray를 막는가?
```

현재 벽·기둥·큰 시험 상자에는 두 속성이 모두 있다. 바닥·디버그 선·UI는 시야를 막지 않는다. 이후 유리 전시대는 이동은 막지만 시야는 통과하도록 두 속성을 다르게 지정할 수 있다.

## 실제 확인 결과

2026-08-25 로컬 장면에서 다음을 확인했다.

- 열린 공간에서 `VISIBLE`, 약 1.2초 뒤 `DETECTED 100%`
- 35% 이상에서 경비가 `SUSPICIOUS`로 정지하고 플레이어 방향 확인
- 큰 상자 뒤에서 `BLOCKED`와 `collision-test-crate` 차단 이름 표시
- 차폐 후 `SUSPICIOUS → CLEAR 0%`로 자연스럽게 감소
- 완전히 거리 밖이면 `OUT_OF_RANGE`이고 Raycast를 실행하지 않음
- 경비 회전과 손전등·Vision 방향이 함께 변경
- 초당 약 20회 시야 검사
- F1 디버그 토글 정상
- 약 165 FPS, 콘솔 경고·오류 없음
