# 3D 결과·재시작·게임 오버 — Phase 13

이 문서는 한 판이 **시작 → 성공 또는 실패 → 결과 확인 → 재시도**로 완전히 순환하도록 만든 구조를 초보 개발자도 이해할 수 있게 설명한다.

## 플레이 흐름

```text
MAIN MENU
→ PLAYING
→ COMPLETE 또는 FAILED
→ 짧은 종료 연출
→ RESULT
→ RETRY 또는 MAIN MENU
```

성공은 왕관을 가진 상태로 탈출 지점에 도착했을 때만 발생한다. 체포는 경비 시야와 추격 판정을 통과한 경우에만 기존 Guard AI가 요청하며, 실패 이유는 결과 화면까지 보존된다.

## 기록과 점수

`RunStats`는 플레이 중인 시간만 계산한다. 메뉴·일시정지·결과 화면에서는 시간이 증가하지 않는다. 발각과 추격은 매 프레임 더하지 않고, 상태가 처음 시작되는 순간만 한 번 기록한다.

| 항목 | 점수 |
|---|---:|
| 왕관 | 10,000 |
| 골동품 시계 | 1,000 |
| 왕실 문서 | 2,000 |
| 다이아몬드 브로치 | 3,000 |
| 무발각 | 5,000 |
| 1회 발각 | 3,000 |
| 2회 발각 | 1,500 |
| 5분 미만 | 2,000 |
| 7분 미만 | 1,000 |
| 10분 미만 | 500 |

최대 점수는 21,000점이다. 점수 비율이 90% 이상이면 S, 75% 이상이면 A, 55% 이상이면 B, 나머지는 C 랭크다. 왕관·선택 보물 3개·무발각을 모두 달성하면 `PERFECT HEIST`가 표시된다.

최고 점수와 최단 시간은 브라우저 `localStorage`에 저장한다. 저장소를 사용할 수 없는 시크릿·제한 환경에서도 결과 화면은 정상 동작하도록 예외를 무시한다. `O` 강제 성공과 `P` 강제 실패는 테스트용이므로 최고 기록에 저장하지 않는다.

## UI

- 메인 메뉴: 작전 시작과 기본 조작 안내
- 일시정지: `ESC`, 계속하기, 재시작, 메인 메뉴
- 재시작 확인: 실수로 진행 상황을 지우지 않도록 한 번 더 확인
- 성공 결과: 랭크, 왕관, 선택 보물, 발각, 추격, 시간, 점수, 최고 기록
- 실패 결과: 실패 원인과 실패 시점의 수집·시간 기록
- 종료 화면 동안 현재 3D 장면은 어둡게 흐려져 결과에 집중한다.

## 재시작 구조

`RunResetManager`가 0.32초 암전 사이에 기존 `resetCrownHall()`을 호출한다. 페이지를 새로고침하지 않으므로 GLB와 Babylon.js 씬을 다시 내려받지 않는다.

초기화되는 주요 항목은 다음과 같다.

- 플레이어 위치·속도·입력·애니메이션
- 경비 2명의 FSM·기억·수색·순찰·애니메이션
- 탐지 게이지·소음·청각·무전
- 왕관·전시대·선택 보물 3개
- 경보·봉쇄·게이트·CCTV·비상 통로
- 은신 상태·상호작용 선택·카메라
- 실행 시간·발각·추격·수집 기록
- 결과·경보·은신·상호작용 UI

## 테스트 방법

1. `npm run dev` 후 `/3d.html`을 연다.
2. `PLAY HEIST`를 누르고 `ESC`로 일시정지·계속하기를 확인한다.
3. 재시작 확인에서 취소와 실제 재시작을 각각 확인한다.
4. 개발 빌드에서는 `O`로 성공, `P`로 실패 결과를 빠르게 확인한다.
5. `RETRY` 후 보물, 경보, 경비, 시간, UI가 처음 상태인지 확인한다.
6. 실제 플레이로 왕관을 얻은 뒤 출구에 도착해 결과와 최고 기록 저장을 확인한다.
