# 플레이테스트 도구와 밸런스 설정

이 문서는 F2 개발자 패널과 `balance.ts`에서 게임 수치를 조정하는 방법을 설명한다.

## F2 테스트 패널

게임 실행 중 F2를 누르면 오른쪽에 테스트 패널이 열린다. 다시 F2를 누르거나 × 버튼을 누르면 닫힌다. 패널을 열어도 게임은 계속 진행된다.

### 실시간 표시 정보

- 게임 상태와 플레이 시간
- 플레이어 좌표와 이동 자세
- 플레이어의 실제 속도와 이번 프레임 실제 이동 거리
- 걷기 방향, 보행 주기 위치, 현재 프레임 번호
- 캐릭터 아래쪽 중앙 피벗 종류와 월드 좌표
- 알파·브라보 경비 발소리의 현재 거리 음량 비율
- 노출도와 현재 발소리 범위
- 알파·브라보 경비의 AI 상태와 감지율
- 전역 경계 단계와 현재 감지 중인 CCTV 수
- 맵 탐색률과 출구 봉쇄 남은 시간
- 무전 횟수와 보물 획득 수
- 경비 발소리 신호, 신호 뒤 멈춤과 방향 전환 횟수
- 첫 위험음과 첫 보물까지 걸린 시간

이 정보는 약 0.15초 간격으로 갱신한다. 매 화면마다 HTML을 다시 만드는 비용을 줄이면서도 사람이 보기에는 충분히 빠른 간격이다.

## 디버그 표시

| 선택 항목 | 동작 |
|---|---|
| 경비 이동 경로 표시 | 알파와 브라보가 현재 따라가는 A* 경로를 안개 위에 표시한다. |
| 플레이어 소음 파동 표시 | 이동할 때 발생하는 원형 소음 범위를 표시하거나 숨긴다. |

경비 경로는 개발자 확인용이라 시야 밖에서도 보인다. 실제 난이도를 평가할 때는 끄고 플레이해야 한다.

## 최근 플레이 기록

패널은 브라우저 로컬 스토리지에 저장된 최근 플레이 중 마지막 5개를 보여준다.

- 탈출 성공 또는 체포
- 플레이 시간
- 확보한 보물 수
- 최종 점수

`JSON 내보내기`를 누르면 전체 저장 기록을 날짜가 포함된 JSON 파일로 내려받는다. `기록 초기화`는 확인창에서 동의한 뒤 현재 브라우저의 기록만 삭제한다.

기록되는 전체 항목은 [플레이테스트](playtest.md#자동-저장-항목)에서 설명한다.

## 밸런스 설정 파일

자주 조정하는 숫자는 [src/balance.ts](../src/balance.ts)에 모아 두었다.

| 그룹 | 담당 값 |
|---|---|
| `player` | 기본 걷기·달리기·웅크리기 속도, 기본 시야, 웅크리기 탐지 배율 |
| `noise` | 자세별 소음 거리·간격, 보물 가산치, 벽 차폐율 |
| `guard` | 평상시·추격 시야 거리와 각도, 정전 구역 시야 배율 |
| `lighting` | 정전 시 플레이어 시야 배율, 스위치 대기시간, 경비 조사 반경 |
| `cctv` | 밝기와 경계 단계에 따른 감지 거리·속도 |
| `scoring` | 보물 배수, 시간 보너스, 완전 잠입 보너스 |
| `lockdown` | CCTV·마지막 보물의 출구 봉쇄 시간 |

예를 들어 웅크리기가 너무 강하다면 `crouchDetectionMultiplier`를 `0.7`에서 `0.8`로 올린다. 숫자가 높을수록 경비와 CCTV가 웅크린 플레이어를 더 쉽게 발견한다. 정전이 지나치게 강하면 `darkZoneVisionMultiplier`를 `0.85`보다 높이고, 약하면 낮춘다.

## 안전한 조정 순서

1. 한 번에 한 종류의 값만 바꾼다.
2. `npm run build`로 자료형 오류를 확인한다.
3. 같은 경로를 최소 3번 플레이한다.
4. F2 패널에서 결과를 JSON으로 내보낸다.
5. 이전 결과와 비교한 뒤 값을 유지하거나 되돌린다.

여러 값을 동시에 바꾸면 어떤 변경이 재미에 영향을 줬는지 알기 어렵다.

## 직접 확인할 것

- F2로 패널이 열리고 닫히는가?
- 실시간 수치가 플레이 상황과 함께 바뀌는가?
- 경비 경로와 소음 파동 선택 항목이 즉시 적용되는가?
- 게임 종료 후 최근 기록이 추가되는가?
- JSON 파일에 전체 기록이 들어 있는가?
- 기록 초기화 취소 시 데이터가 유지되는가?
- 설정값을 수정한 뒤 빌드와 실제 게임에 반영되는가?
