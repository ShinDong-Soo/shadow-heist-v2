# 캐릭터 에셋

이 문서는 플레이어와 경비원 캐릭터의 외형, 이미지 파일, 게임 적용 방식을 한곳에서 관리한다. 캐릭터 관련 내용을 수정할 때는 다른 문서에 같은 설명을 복사하지 말고 이 문서를 갱신한다.

## 현재 사용 중인 에셋

| 역할 | 파일 | 용도 | 게임 표시 크기 |
|---|---|---:|---|
| 플레이어 | `public/assets/characters/stealth-thief-walk-4x4-v4.png` | 4방향 걷기 | 82 × 82px |
| 일반 경비원 | `public/assets/characters/museum-guard-walk-4x4.png` | 4방향 걷기 | 84 × 84px |
| 플레이어 예비 이미지 | `public/assets/characters/stealth-thief.png` | 로딩 실패 대비 | 68 × 68px |
| 경비원 예비 이미지 | `public/assets/characters/museum-guard.png` | 로딩 실패 대비 | 72 × 72px |

걷기 시트는 1024 × 1024px, 예비 이미지는 512 × 512px PNG이며 모두 배경이 투명하다. 원본을 게임 화면에서 작게 줄여 그리므로, 확대했을 때의 세부 묘사보다 축소했을 때의 실루엣이 더 중요하다.

## 플레이어: 기본 잠입 도둑

- 어두운 후드와 마스크로 얼굴을 가린 현실적인 잠입 전문가다.
- 등에 백팩을 메고 한 손에는 손전등, 다른 손에는 락픽을 들고 있다.
- 빠르게 달리기보다 조심스럽고 민첩하게 움직이는 인상을 준다.
- 보물을 획득하면 캐릭터 옆에 작은 금색 표시가 추가된다.
- `C`로 웅크리면 이미지의 세로 길이를 줄여 자세 변화를 보여 준다.
- 입력한 이동 방향에 맞는 걷기 프레임을 재생한다.
- 실제로 이동한 거리만큼 프레임이 진행되므로 벽에 막혔을 때 제자리 걷기를 하지 않는다.

## 경비원: 일반 박물관 보안요원

- 짙은 남색 제복과 모자를 착용한다.
- 무전기, 열쇠, 손전등이 보여 순찰과 시설 관리 역할을 바로 알아볼 수 있다.
- 알파와 브라보 경비원은 같은 기본 에셋을 사용한다.
- 두 경비원은 발밑 테두리 색으로 구분한다. 알파는 금색, 브라보는 청색이다.
- 조사 상태는 주황색, 추격 상태는 붉은색 빛과 테두리로 강조한다.
- `?`, `…`, `!` 상태 표시는 캐릭터 머리 위에 표시한다.

## 4방향 걷기 시트 구조

걷기 시트 한 장에는 4열 × 4행, 총 16개의 동작이 들어 있다.

| 행 | 방향 | 화면에서 보이는 모습 |
|---:|---|---|
| 1 | 아래쪽 | 캐릭터의 정면 |
| 2 | 왼쪽 | 캐릭터의 왼쪽 이동 |
| 3 | 오른쪽 | 캐릭터의 오른쪽 이동 |
| 4 | 위쪽 | 캐릭터의 등과 백팩 |

각 행의 네 열에는 왼발 디딤, 다리 통과, 오른발 디딤, 반대쪽 다리 통과 순서가 들어 있다. `directionFromAngle()`이 플레이어 입력 또는 경비원의 실제 이동 경로를 네 방향 중 하나로 바꾼다.

플레이어 v4 시트는 모든 프레임을 256 × 256px 고정 셀에 넣었다. 각 셀 안의 캐릭터 높이는 212px, 발 착지선은 셀 위에서 238px 지점으로 통일했다. `drawCharacterFrame()`은 투명 여백을 포함한 셀 전체를 그리며 다음 두 기준을 항상 유지한다.

- 모든 프레임의 발끝을 같은 착지선에 맞춘다.
- 모든 프레임의 키를 같은 높이로 맞추고 가로 비율은 유지한다.

이 처리가 없으면 프레임이 바뀔 때 캐릭터가 좌우로 미끄러지거나 방향 전환 순간에 크기가 달라 보인다. 월드 좌표에 고정되는 피벗은 캐릭터의 `아래쪽 중앙(bottom-center)`이다.

플레이어 v4는 영상에서 정상으로 확인된 6시 방향 행을 유지하고, 모든 방향에서 `왼발 디딤 → 다리 통과 → 오른발 디딤 → 반대쪽 통과` 순서를 사용한다. 왼쪽 이동은 오른쪽 이동 행을 가로로 뒤집어 그린다. 같은 보행 동작을 뒤집는 방식이라 좌우의 보폭과 몸 크기가 정확히 같고, 프레임 순서를 거꾸로 재생하지 않는다.

캐릭터의 월드 좌표는 몸 중앙이 아니라 발이 바닥에 닿는 지점으로 사용한다. 스프라이트의 발끝, 그림자, 충돌 원의 중심을 가까이 맞춰 문이나 장치 앞에서 몸이 위에 포개지는 느낌을 줄였다.

## 재생 속도

- 플레이어 일반 이동: 실제 이동 거리 140px마다 4프레임 한 바퀴
- 플레이어 조심 걷기: 실제 이동 거리 136px마다 4프레임 한 바퀴
- 플레이어 웅크리기: 실제 이동 거리 128px마다 4프레임 한 바퀴
- 경비원 순찰·조사: 실제 이동 거리 약 12px마다 다음 프레임
- 경비원 추격: 실제 이동 거리 약 16px마다 다음 프레임
- 실제 속도 5px/s 미만의 정지 상태: 첫 번째 착지 프레임에서 정지

시간이 아니라 실제 이동 거리를 사용하는 이유는 간단하다. 캐릭터가 빨라지면 애니메이션도 자연스럽게 빨라지고, 벽이나 장애물에 막혀 이동 거리가 0이면 다리도 즉시 멈춘다. 플레이어의 한 보행 주기는 발소리 두 번이 발생하는 실제 이동 거리와 비슷하게 맞췄다. 이 값은 `src/main.ts`의 `PLAYER_ANIMATION`에서 조정할 수 있다. 플레이어와 알파·브라보 경비원 모두 실제 이동 거리 원칙을 사용한다.

표시 방향도 키 입력이나 목표 지점만 보지 않고 충돌 계산이 끝난 뒤 실제로 움직인 방향을 사용한다. 대각선으로 벽을 밀다가 벽면을 따라 이동하면 캐릭터도 실제 미끄러지는 방향을 바라본다. 방향이 바뀔 때는 첫 착지 프레임부터 다시 시작해 다리가 순간적으로 뒤바뀌는 현상을 줄인다.

완전한 8방향 애니메이션이 필요해지면 북동·북서·남동·남서 방향 행을 추가하거나 방향별 파일을 나누는 방식으로 확장할 수 있다.

## 코드 연결 구조

`src/character-assets.ts`가 PNG 파일을 미리 불러오고 방향 계산, 실제 프레임 영역, 발 기준 정렬을 담당한다. `src/main.ts`는 플레이어와 경비원이 실제로 이동한 거리를 누적하고 그 거리에 맞는 프레임을 요청한다. 이미지가 아직 준비되지 않았거나 파일을 찾지 못하면 기존 Canvas 도형 캐릭터를 그린다.

이 예비 그림 덕분에 느린 네트워크에서도 캐릭터가 잠시 사라지지 않는다.

## 에셋 교체 방법

1. 새 PNG의 배경이 실제로 투명한지 확인한다.
2. 16개 캐릭터가 서로 겹치거나 이미지 바깥에서 잘리지 않았는지 확인한다.
3. 기존 파일명과 같은 이름으로 `public/assets/characters/`에 넣는다.
4. 새 그림의 위치가 기존과 다르면 `src/character-assets.ts`의 `playerWalkFrames` 또는 `guardWalkFrames` 좌표도 수정한다.
5. `npm run build`를 실행한다.
6. 게임에서 상·하·좌·우 이동, 정지, 벽 밀기, 웅크리기, 조사, 추격 상태를 확인한다.

파일명을 바꾸려면 `src/character-assets.ts`의 경로도 함께 바꿔야 한다.

## 직접 확인할 항목

- 어두운 바닥에서도 플레이어와 경비원의 윤곽이 구분되는가?
- 플레이어의 후드·마스크와 경비원의 제복이 작은 화면에서도 다르게 보이는가?
- 캐릭터 이미지 주변에 흰색 또는 체크무늬 사각형이 남지 않는가?
- 상·하·좌·우 이동 때 올바른 행의 프레임이 표시되는가?
- 프레임이 바뀔 때 발 위치와 몸 중심이 좌우로 튀지 않는가?
- 정지했을 때 프레임 재생도 함께 멈추는가?
- 벽을 계속 밀어도 제자리 걷기와 발소리가 발생하지 않는가?
- 벽면을 따라 미끄러질 때 실제 이동 방향으로 걷는가?
- 문, 제어 장치, 은신 설비 앞에서 캐릭터의 발과 몸이 겹치지 않는가?
- 일반 이동, 조심 걷기, 웅크리기의 발 움직임 속도가 실제 이동 속도와 어울리는가?
- 경비원 상태 표시가 머리와 겹치지 않는가?
- 벽 가까이에서 플레이어와 경비원의 몸이 가로로 잘려 보이지 않는가?
