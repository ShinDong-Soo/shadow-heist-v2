# Codex 협업 기록

이 문서는 Shadow Heist V2 개발에서 개발자와 Codex가 맡은 역할을 사실에 근거해 정리한다.

## 역할 구분

개발자는 게임의 핵심 방향, 구현 우선순위, 캐릭터 콘셉트와 최종 적용 여부를 결정했다. Codex는 요청받은 범위 안에서 코드 조사, 기능 구현, 오류 수정, 빌드 검사와 초보자용 개발 문서 정리를 지원했다.

## 경비 AI와 잠입 규칙

문제:

- 경비가 순찰만 하면 소리로 유도하는 재미를 검증하기 어렵다.
- 기능이 많아질수록 경비가 왜 움직였는지 이해하기 어려워진다.

Codex 기여:

- 순찰, 의심, 조사, 추격, 수색, 은신처 확인 상태를 코드로 연결했다.
- 발소리, 문, 조명, CCTV와 무전 보고가 조사 위치로 이어지게 구현했다.
- Prototype 17에서 경비 머리 위에 행동 원인을 잠시 표시하도록 개선했다.

개발자 결정:

- 경비 종류를 계속 추가하지 않고 두 경비의 정보 전달과 공정성을 먼저 다듬기로 했다.

## LOS와 시야 밖 어둠

문제:

- 벽 너머가 보이면 잠입 규칙이 무너진다.
- 모든 길을 계속 밝히면 제한된 정보에서 오는 긴장감이 사라진다.

Codex 기여:

- 벽과 닫힌 문을 반영하는 LOS 계산을 분리했다.
- 현재 시야를 벽과 닫힌 문에 맞춰 잘라 표시하도록 연결했다.
- 경비, CCTV와 조명이 같은 LOS 장애물 규칙을 사용하게 정리했다.

개발자 결정:

- Prototype 27부터 지나온 경로의 기억 표시는 제거하고 현재 LOS 밖을 완전히 가리는 방향으로 변경했다.

## 소리와 긴장감 계측

문제:

- 경비 소리가 존재하는 것과 플레이어가 소리에 반응하는 것은 다르다.

Codex 기여:

- 두 경비의 발소리를 각각 거리 감쇠, 좌우 패닝, 벽 차폐와 함께 재생하도록 개선했다.
- 첫 위험음 시간, 위험음 뒤 멈춤, 방향 전환, 첫 탐지, 첫 보물 시간을 플레이 기록에 추가했다.
- F2 패널과 JSON 내보내기를 사용해 결과를 비교할 수 있게 했다.

개발자 결정:

- 핵심 검증 질문을 “경비가 안 보일 때 긴장되는가”, “소리로 위치를 추측하는가”, “보물 뒤 귀환이 긴장되는가”로 유지했다.

## 캐릭터 에셋

문제:

- 단일 캐릭터 이미지를 흔들거나 좌우 반전하는 방식은 방향별 걷기로 보이지 않았다.

Codex 기여:

- 개발자가 제공한 플레이어·경비원 설명과 참고 이미지를 게임용 에셋으로 변환했다.
- 네 방향 × 네 프레임 걷기 시트를 생성하고 투명 배경으로 후처리했다.
- 이동 방향과 속도에 맞는 프레임을 선택하는 Canvas 렌더링을 구현했다.

개발자 결정:

- 후드·마스크·백팩의 잠입 도둑과 제복·무전기·열쇠의 박물관 경비원 콘셉트를 확정했다.

## 검증과 문서화

- Codex는 각 개발 단계에서 `npm run build`와 변경 파일 검사를 수행했다.
- 구현 내용은 사운드, UI, 캐릭터, AI 등 분야별 Markdown 문서에 중복 없이 기록했다.
- 주요 기존 커밋: `bf6b046`, `dc55e98`, `de94f3c`

이 문서는 실제 협업 내용을 기록하기 위한 것이며, 수행하지 않은 작업이나 존재하지 않는 결과를 추가하지 않는다.
